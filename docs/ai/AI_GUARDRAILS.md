# AI Guardrails

本文档定义 ent 仓库中 AI coding agent 的权限等级、禁止事项和默认执行边界。任何任务开始前，都应把本文件与 `AGENTS.md` 作为约束源。

## 授权等级

| Level | 名称 | 允许行为 | 禁止行为 | 适用场景 |
| --- | --- | --- | --- | --- |
| L0 | 咨询级 | 只回答问题，不读仓库，不改文件 | 运行命令、读取本地文件、修改文件 | 解释概念、讨论方案 |
| L1 | 只读扫描级 | `rg`、读文件、看 diff、分析调用链 | 修改文件、生成补丁、提交 | impact-scan、review 前置分析 |
| L2 | 补丁草案级 | 修改工作区、运行本地验证、输出 diff summary | 提交、push、创建 PR | 小范围实现、文档更新、测试补充 |
| L3 | 分支提交级 | 新建分支、修改、测试、提交 | 合并、force push、发布 release | 明确授权的完整任务闭环 |
| L4 | PR 级 | 创建 PR、更新 PR 描述、响应 review | merge、绕过 CI、改保护分支 | 需要 GitHub 协作的任务 |
| L5 | 自动合并级 | 自动合并 | ent 当前禁止使用 | 当前不允许 |

默认授权等级是 L2。进入 L3 或 L4 必须由用户明确要求。L5 在 ent 仓库当前禁止使用。

## 永远禁止

- 直接 merge 到 `master` / `main`。
- force push。
- 删除、跳过或弱化测试换取通过。
- 没有任务卡的大范围重构。
- 跨模块顺手优化。
- 未说明原因修改 CI。
- 修改 public API 但不补测试或文档。
- 修改路径、权限、delete、rename、truncate 语义但不补测试。
- 伪造测试通过。
- 把环境失败描述为代码已验证通过。
- 将未运行的本地命令、CI job 或 benchmark 写成已通过。
- 在用户未授权时提交、push、创建 PR 或合并。
- 覆盖用户未提交修改。

## 默认要求

- 每轮任务必须有目标、非目标、允许范围、禁止范围、验收命令。
- 每轮只做一个小闭环，默认不合并多个主题。
- 每轮最终输出必须列出未验证项。
- 高风险模块必须先做 impact-scan。
- review 与实现尽量分离，review 输出应基于 diff 和证据。
- CI 是最终事实裁判；本地通过不能覆盖 CI 失败。
- Codex 不能自己定义完成标准后自证完成，完成标准必须来自任务卡或用户确认。
- 没有验收命令的任务不应执行，除非先补出建议并得到用户认可。

## 风险等级

| Risk | 定义 | 处理要求 |
| --- | --- | --- |
| R0 | 纯文档、注释、非行为治理文件 | 可 L2 执行，仍需 `git diff --check` |
| R1 | 测试、示例、非 public 文档 | 需要运行相关测试或说明未验证项 |
| R2 | 单模块业务逻辑或错误码使用 | 需要 impact-scan、局部测试、回归命令 |
| R3 | public API / ABI、并发、生命周期、CI、跨平台路径 | 必须先 impact-scan，建议独立 review gate 和 CI gate |

## 审计证据链

一次合格 AI 修改至少需要以下证据：

- 任务卡或用户明确边界。
- 修改文件清单。
- diff summary。
- 本地命令输出摘要。
- CI 链接或说明未触发 CI。
- 未验证项。
- rollback 路径，例如 revert commit、删除新增文件或恢复配置。
